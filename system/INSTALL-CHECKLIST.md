# AI 辅助搭建检查表

这个文件就是任务路线，不需要使用者再写一段“万能提示词”。AI 根据实际回答填写检查记录；未完成项保留，不自行勾选。

## 0. 环境调查

- [ ] 确认 Windows/macOS/Linux、Obsidian 桌面/手机系统、是否有现成库、是否有常开服务器。
- [ ] 确认目标为 L0/L1/L2/L3；有旧库先备份，不初始化、不覆盖它。
- [ ] 记录 Python、Node、Docker CLI 与引擎、网络、磁盘和端口的实际结果。
- [ ] 区分本机库路径、容器路径、服务器路径、手机库名；不假定它们相同。
- [ ] 确认自己的 HTTPS 域名/证书、服务凭证、外部音频处理许可和模型费用范围。

## 1. 先在虚构库演示

- [ ] `tools/system.py init --home <新目录> --demo`，本机启动确认中心。
- [ ] 登录、提交真实输入的示例答复；核对只进入投稿、没有直接变正式知识。
- [ ] 运行参考整理提交与 `resolve`，刷新页面只在最终回执后显示已入库。
- [ ] 运行单元测试、备份、恢复到另一新目录；比对原始文件 hash。

## 2. 同步基础

- [ ] 生成自己的私有配置；检查 Git 忽略及操作系统权限。
- [ ] 启动 CouchDB，初始化独立用户与数据库权限，再启动只读 MCP。
- [ ] 配置 HTTPS 与明确 CORS；未授权访问被拒绝。
- [ ] 全新桌面库与全新手机库采用同一数据库、E2E passphrase、混淆/大小写设置。
- [ ] 手机→服务器→桌面、桌面→服务器→手机，分别检查文本、附件大小及 SHA256。
- [ ] 同步离线后重连、冲突处理、只读 MCP 写入被拒绝。

## 3. 知识处理

- [ ] 新库先建立目录/规则/空索引；现成库只出差异计划。
- [ ] 在隔离新 MCP 实例集成生产参考扩展，固定上游版本和运行依赖。
- [ ] reader/proposal/curator/meeting 独立身份；真实服务器越权拒绝验证。
- [ ] 长文 prepare/context_read/stage/commit 范围、断点、重放、版本冲突测试。
- [ ] 只配置一个整理负责人及一套单写控制器，复用平台现有任务。
- [ ] 每日增量、每日结构、每周语义/时效检查；运行真实一轮并查看实际成果。

## 4. 会议、声纹与确认

- [ ] 音频稳定等待、hash 去重、断点恢复；同音频重试不重复提交收费任务。
- [ ] 使用自己的听悟账号完成一段获授权音频，保留原始 JSON 和任务 ID。
- [ ] 纪要与完整转写同源、sentence 锚点可回查；数字和归属核完整转写。
- [ ] 安装自己的模型，声纹结果只进入私有存储，UI 试听有效。
- [ ] 人工确认/自动匹配分开；更名或撤销能修正旧归属并保留事件历史。
- [ ] 确认题与答复 ID/version 一致；最终 PASS + maintenance_finalized 才显示入库。
- [ ] 词典停止重复提问；多义词不自动合并；热词只影响新识别任务。

## 5. 切换和交付

- [ ] 保存真实配置的私有位置，不提交密钥、音频、声纹、卡片、历史日志或手机 setup URI。
- [ ] 规则、本地 Skill、部署 Skill、平台共享 Skill、Bot、任务、看板、权限逐项记录。
- [ ] 真实设备试验由实际手机完成；模拟窄屏/服务器下载不可代替。
- [ ] 交付自己的运维文档、版本、未通过项、备份及恢复记录。

给使用者报告“已完成等级、实际测试、未通过项、下一步”。不要把 L1 的成功描述为整套知识系统已经搭好。
