# Worker 回路规格：模型一半

`curation_host.py` 是"确定性一半"（租约、journal、原子写入、回读）。本文件规定"模型一半"：一个定时被唤醒的 Agent 按什么顺序调用宿主、做什么判断、产出什么回执。两者合起来才是 24 小时整理 Worker。

模型一半不是一段可复制的代码，而是一份**运行契约**：在你自己的平台（cron + Agent API、systemd timer、或任何定时任务）上实现下面这个回路。判定标准只有一个——**确定性动作全部走宿主，理解和判断全部由模型按 ingest Skill 完成**，两者不互相冒充。

## 回路（每次唤醒执行）

```text
1. 唤醒 → 调宿主 pending，取待处理来源列表
   无待处理 → 写一条空跑记录，结束（不伪造工作量）
2. writer_acquire(owner=本任务名, purpose=本轮目标)
   BUSY → 结束本轮（不抢占、不等待、不换身份重做）
3. 按优先级取一个来源：确认答复 > 会议 > 日记 > 其他
   答复不计入普通资料数量上限
4. prepare(token, source_id, old_pages=[按 ingest Skill 判定的相关旧页])
   记录返回的 rule_version；来源快照即被绑定
5. source_read 从 offset=0 连续读到 next_offset=null
   读齐之前不做任何判断；版本变化 → 放弃本轮，下轮重来
6. 按 ingest Skill 理解来源、对照旧知识，逐项判定
   create / update / covered / none，写出带逐字引文的 proposal
   无可提炼内容 → 判 no_knowledge 并说明原因，不空写
7. commit(token, proposal)
   失败 → 按宿主返回的错误分类处理：
     快照/版本冲突 → 放弃本轮（下轮重 prepare）
     同 token 同参数 → 幂等恢复（读回 commit_key，不重做）
     其他 → 写失败记录，结束本轮
8. verify(commit_key) → 必须 verified=true 才算本轮成功
9. writer_release(token)
10. 写本轮报告：来源、判定、commit_key、verify 结果、未读范围
```

## 调度建议

| 回路 | 频率 | 说明 |
|---|---|---|
| 普通增量 | 每小时 | 每轮限量（如 3 份来源），答复优先且不限量 |
| 结构巡检 | 每天 | 调 health Skill；只读回执/台账做交叉核对 |
| 语义巡检 | 每周 | lint 批次；在预算内分批，不冒充全库完成 |
| 日报 | 固定时刻 | 独立于模型任务是否成功；失败/未知分开列 |

任务分工与验收证据见 [07-growth.md](../runbooks/07-growth.md) 的"调度和控制器"节；定时示例见 `cron.example`（cron 只能调度确定性动作，模型回路需另配平台定时任务）。

## 平台必须提供的能力（检查清单）

- [ ] 定时唤醒：cron、systemd timer、平台定时任务三选一；同一库只配一个调度源
- [ ] 模型调用： wakes 时带上 ingest Skill 上下文；API Key 在平台侧保管，不进仓库
- [ ] 预算与暂停：每轮最大来源数、最大费用、何时暂停、谁可暂停；自动恢复默认关闭
- [ ] 日志：每轮报告独立可查；失败原因与受影响范围不静默跳过
- [ ] 凭证隔离：宿主 state 目录仅运行用户可读写；模型看不到宿主内部 token 以外的秘密

## 失败与边界

- 租约 BUSY、来源快照变化、旧页版本冲突 → 都是**正常**的并发信号，放弃本轮等下轮，不视为故障。
- 当天有未整理来源而真实入库数为 0 → 报每日入库故障（见 health Skill），不是"任务完成"。
- 模型永远不直接写知识文件：一切写入走宿主 commit；宿主永远不调模型、不做语义判断。任何一侧越界都是实现错误。
- 不联网：ingest 按 Skill 先查库内；需外部核对的标出留给巡检，不把外部候选写入正式知识。
