# 声纹库、发言人和人物页

前置：完整转写、原音频和导入回执均可核验。模型环境位于自己的 `/opt/kb-voiceprint`，私有状态位于 `/var/lib/kb-voiceprint`。源码不是附带模型的识别服务，配置示例也不会自动安装模型。

## 模型与处理链

1. 为声纹单独创建 Python 环境；按 `vp_extract.py` 的真实 import 安装 `numpy`、`av`、`sherpa-onnx`。从模型提供方取得允许使用的模型，记录来源、版本、文件 SHA-256 和许可；不要下载来历不明的“同名模型”。
2. 根据源码设置模型文件路径、16 kHz 音频输入及切片参数。`system/config/voiceprint.example.json` 是参数合同，原脚本仍需接线；不能只放这个 JSON 就宣称配置已生效。
3. `vp_extract.py` 提取片段向量，后续聚类、试听片段和引文脚本生成**私有**候选。`kb_voiceprint_watch.py` 按任务回执发现新会议，限制每轮处理量，并用锁和持久记录避免并发重复。
4. `make_speaker_cards.py` / watch 生成身份卡，`vp_predict.py` 给出候选。卡片同时提供文字证据与可试听片段，让本人判断。

原提取脚本的音频后缀与上传器接受范围不完全相同。AAC/CAF/MP4 等输入须先验证解码路径或生成带原件引用的派生音频；失败应报告“不支持/待转换”，不能默默丢掉该会议。

## 人工确认是注册依据

`OWNER_CONFIRMED` 表示主人实际确认过；`AUTO_MATCH` 表示相似度推测，两者必须分别保存、分别展示。自动匹配不能自行成为下一轮的人工训练锚点。样本质量、时长、干净片段数、同会议身份冲突和候选间差距都要符合条件；不足就保留“未知/待确认”。

同一个声音不一定等于同一个真实人物；同名也不能自动合并。人物所属领域、可用范围和身份须明确授权。`kb_person_attendance.py`、`kb_person_reconcile.py`、`kb_person_profile.py`、`kb_person_daily.py` 根据已确认身份、完整转写和允许范围维护人物页，写入时仍取得同一 writer lease。

## 撤销和隐私

撤销身份需要重算声音库锚点、自动匹配、派生纪要名字、人物页归属、词典与卡片。旧事件保留为历史；不直接改原始识别 JSON。原系统的迟延窗口与状态文件要一起迁移，不能只复制 `voices.json`。

声音片段、向量、人物名字、身份映射、会议哈希和试听地址均按私人数据处理，不上传公开仓库。试听路由要会话鉴权、限定 ID 和目录，不能让客户端提交任意文件路径。

## 验收

使用有授权的两位发言人测试：未知 → 主人确认 → 新会议候选 → 人工/自动来源分别可见；再测试同会议冲突、混合说话、短片段、认错后的撤销与人物页回读。检查身份改变后旧错误归属不再继续传播。

仓库本地演示卡没有真实音频和向量。页面能点名字，只能说明界面交互存在，不能算声纹服务、模型准确率或人物页闭环验收。
