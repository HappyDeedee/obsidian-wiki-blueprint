# Agent 建库任务书

目标不是照抄作者服务器，而是在搭建者自己的环境复现相同的知识流程。

## 先读取并报告

仅当确实缺失时向用户确认：目标新库路径、来源授权范围、电脑/手机/云端需求、可用 Agent、模型预算、同步方案和是否需要网页确认中心。不要索取可放进公开仓库的密钥；凭证通过目标环境的私密配置传入。

建库前输出一张能力表：Python、Obsidian、Agent、Markdown 读写、可用 MCP 工具、角色隔离、版本保护、同步、OCR/转写、调度、备份。每项标“已验证 / 待配置 / 不需要”，附实际证据。不要把本仓库列出的接口当作已经安装。

## 六个阶段

| 阶段 | 动作 | 进入下一阶段的依据 |
|---|---|---|
| 0 隔离 | 新建测试目录，不连接真实库 | 目录明确为空，无生产凭证 |
| 1 参考闭环 | init、demo、query、health、tests | 原件哈希未变，两个版本的知识变更有回执，答复不重复采纳 |
| 2 基础接入 | 按自己的环境安装 Obsidian/Agent，映射基础工具 | 可读规则、分段正文、搜索、列目录；只读身份写入被拒绝 |
| 3 生产适配 | 实现 curation 合同、持久租约、断点、权限 | 按 docs/08 的并发、改版、崩溃、重放测试通过 |
| 4 自动化 | 单一调度器、确认中心、格式转换、同步与备份 | 真实排队运行、最终回执、文件回读；各设备单独验收 |
| 5 小范围上线 | 用户授权少量真实资料，再扩大 | 来源→知识→回答语义抽检通过，有回滚点 |

## 应交付的本地文件（默认私人，不提交本公开仓库）

- `capabilities.json`：工具、schema、版本、限制和实际测试日期。
- `deployment-manifest.json`：规则/Skill/服务的内容哈希、发布位置与回滚位置。
- `acceptance.md`：命令、真实回执、已查范围、未完成项；不能含令牌。
- `sync-checklist.md`：本地 Skill、部署 Skill、共享 Skill、Bot、任务、看板、权限逐项结果。
- 备份及恢复演练证据；正式来源与输出的对应关系。

推荐先运行本地参考版；若选择生产服务器版，必须完成适配器工作，不能声称本仓库现成提供原生产服务。搭建失败时保留已有成果，停止有关写入，不删除重建原库。
