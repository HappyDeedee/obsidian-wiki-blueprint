# 从空白环境复建整套知识系统

目标是复用工作方式、界面和数据链路。搭建者提供自己的资料、账号、域名和密钥；作者的私人笔记、人物信息、云资源和 MCP 连接不属于安装包。

## 新 AI 的执行顺序

1. 阅读根 `AGENTS.md`、`system/STATE.md` 和 `system/INSTALL-CHECKLIST.md`，先列出本机已有工具与尚缺的条件。
2. 按 `system/runbooks/01-local.md` 在新目录验证本地确认界面、问题答复、提交回执和恢复流程。
3. 按 `system/runbooks/02-sync.md` 配置搭建者自己的 CouchDB 和 LiveSync，分别验证电脑、手机及附件。文件同步、AI 模型代理、远程电脑连接是三种不同服务，不能互相替代。
4. 按 `system/runbooks/03-mcp.md` 接入实际读写服务，完成 `system/source-map.md` 中的宿主集成。原版只读 MCP 不能自动成为本项目的整理服务。
5. 配置会议接收、通义听悟、已确认词典和热词库；先保存原录音与完整转写，再处理纪要、说话人和人物页面。
6. 接入附件转换：原件留在 Inbox，转换文字写入派生目录，失败和未读图片显式登记；文字提取完成之后才进入知识萃取。
7. 启用独立写入身份和单一控制器，完成提问、主人答复、正式提交、最终回执、查询、巡检及备份恢复。
8. 用新环境的虚构资料逐段验收，并记录每台真实设备的结果。缺少的程序、权限和服务必须列为阻塞项，不能用模型猜测补齐后声称与原系统等效。

## 必须交付的内容

| 层次 | 交付物 | 判断是否完成 |
| --- | --- | --- |
| 方法与结构 | 目录用途、来源身份、知识页、索引、日志、时效规则 | 新 AI 能解释资料从哪里来、写到哪里、如何回溯 |
| 服务配置 | 必需/可选服务、配置字段、加载位置、权限、启动与恢复 | 自己的配置能被实际程序读取 |
| 会议处理 | 听悟参数、完整提示词、热词来源、纪要字段和失败状态 | 原录音、转写、纪要、行动证据一致 |
| 随手放文件 | 格式分流、MarkItDown 调用、重复检测、原件保护 | 转换回执与内容哈希对应，不把失败计成功 |
| 确认与生长 | 提问、答复、整理提交、最终回执、撤销边界 | “已收到”与“已入库”有不同证据 |
| 多端同步 | 电脑、手机、服务端和附件逐端测试 | 用真实设备读回同一份新内容，而非只检查服务健康 |

## 脱敏与配置原则

- 发布规则、模板、程序和虚构示例；不发布生产配置、数据库、缓存、音频、日志、私有历史或真实人物词典。
- 地址使用占位域名，凭证由安装时生成或由搭建者填写，保存在仓库外。公开 MCP 工具契约可以保留，作者的连接信息不能保留。
- 替换连接值之后要核对配置确实被程序消费，不能只有一份无人读取的示例 JSON。
- 每个模块记录代码来源、适配差异、测试范围和未完成事项。参考程序、可启动演示、已验收生产部署分别标记。

当前完整生产复建仍受 `system/source-map.md` 的宿主集成任务限制；本页定义搭建和验收顺序，不是等效性证明。
