# 接收、提取和萃取

“文件进来了”“正文提取了”“读完了”“知识更新了”是四件不同的事。

## 1. 接收与提取

保存原件路径、SHA-256、大小、接收时间、来源渠道、授权范围和逻辑来源 ID。文件写入稳定后才提取；不通过改名或删除原件标记完成。

- Markdown/文本：读取正文，保留原始编码异常记录。
- PDF/Office 等：可选 MarkItDown；输出到 `00-Inbox/已提取正文/`，带原件哈希、转换工具版本和覆盖限制。可解析不代表表格、脚注、图片都正确。
- 扫描件/图片：未接 OCR/视觉就标 `requires_ocr_or_vision`，不当空白来源。
- 音频：会议专用入口用自己的转写服务，保存完整转写和句子锚点；自动纪要只作导航。随手放音频未授权转写时仅登记。
- 视频：需单独的视频/音频处理能力；没有就标 `requires_video_processing`。

按原件内容版本去重，转换失败有有限重试与原因。相同文件名冲突不覆盖；原件和提取正文属于同一来源，不各计成功。

日记可默认稳定 6 小时后入队；内容变化重新计稳定期，后续做 refresh。记录日不是所有内容的事件日。不催写，不把 AI 识别待办当用户已决定的任务。

## 2. 萃取前

读取目标库现行规则，发现实际工具 schema。取得唯一 writer；BUSY 就结束本轮。

用 pending 返回的 `source_id/paths/purpose/kind/version`，不要从旧总结或助手记忆新增候选。固定历史队列和每日新增队列分别续跑；新的资料不必等待历史全量结束。

prepare 返回来源快照、规则/索引/总览版本和相关旧页。搜索用于定位，随后读旧页正文。覆盖不足必须续读，不能只看 catalog、搜索片段或自动纪要就决定 update/covered。

## 3. 长资料

来源与相关旧页是两种阅读游标：

- 来源：按 prepare 的 `read_range` 回读这一范围，Unicode 字符偏移，跟 next_offset 到本范围末端，再 stage；下次 prepare 从真实持久断点继续。
- 旧页：按 context_read 返回的范围读到完整覆盖；不能用它跳过未读来源。
- stage 累积真实主张、逐字短引文、实体/概念判断、历史和矛盾，不自己设置 offset。
- 未读部分不做最终总结。换源版本先核验旧阅读回执是否仍有效。
- 接近工具/时间预算就保存阅读进度；本轮只完成阅读不计入库。大型原文的私有阅读可以独立于短写事务，但导入必须核快照哈希及连续覆盖，不能伪造 offset。

## 4. 决定写什么

每个候选记录 `create/update/covered/none`、理由、目标路径及原文逐字证据。covered 必须读过支持它的旧页。

通常写一份简短来源摘要，并判断关键实体、概念及相关项目；跨来源结论维护在主题页，不往同一摘要无尽堆日报。实体/概念并非必须每篇都建，概念需通过 docs/02 的独立性测试。

已有主题先对照当前结论、时间、对象与条件。相同事实不重复追加；新证据确实改变同范围结论时精确更新，保留旧版全文和依据。冲突未定就保留双方，不能认为较新的文件天然更真。整体理解有变化再维护总览，否则明确不变及理由。

金额、比例、单位、日期、编号、归属与条件逐项回读原句；会议事实以完整转写对应段落为准，纪要不替代转写。同一议题跨会就逐场核对。

问候/导出壳/无新增信息可读齐后 `no_knowledge` 并说明理由；全文真正为空才 empty。代码、公式、失败原因、短决定和个人感受可能有价值；标题、年代、长短、读取失败或附件未读都不是丢弃理由。

## 5. 提交与恢复

模型提出 updates、quotes、候选台账、contradictions、overview_decision；程序验证 schema、权限、来源与旧页 hash、逐字证据、链接及读取覆盖，保存原页备份，持久化 journal，再写成果、索引、日志、台账和断点，最后实际回读。

开始写入前参数错可修正；已 durable/部分提交后必须同 token 同参数恢复。新 token 重做可能重复计数、吞掉中途版本，不能这样“修复”。已成功同版本直接返回原回执，标 reused，不计作新吞吐。

`refresh` 更新已有来源版本；`topic_repair` 修主题/已核答复，不重复摘要和来源数。处理确认答复时按 docs/05，不给每条答复再造来源摘要。

超过 15000 字的正式知识正文不继续 append；读齐后精确改当前段落，重构/拆页/合并须单独确认。合并保留差异、旧页重定向、备份及原始来源，不直接删页。

## 6. 结束

释放自己的 writer；区分首次成功、refresh、修复、reused、stage、无知识与失败。输出真实回执、改动页和剩余范围。结构 PASS 只证明程序覆盖的检查，不证明语义、附件或全库。

日常 ingest 不联网。库内能查清就核原文；需公开查证的留给有外部工具的 health；私人含义或冲突交确认中心。生成答案、输出文件和日志不反向变成独立事实来源。
