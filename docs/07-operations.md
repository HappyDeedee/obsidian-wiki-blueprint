# 巡检、调度、同步与恢复

## 三类检查分开

**结构巡检**：目录/元数据/内部链接/异常日期/明确到期/重复来源版本/实际入库数。程序生成报告，记录时间、实际范围与无法访问项。短链接按 Obsidian 实际解析；不了解解析就只列候选。完整 YAML 列表合法，代码中的 `#` 不当标签。

**内容巡检**：读知识正文和原始证据，检查数字、遗漏主张、新证据未更新旧结论、同范围冲突、重复主题、实体/概念缺失、不可跳转来源。年龄不证明过时，至少三篇引用未解析只触发候选，不自动建页。

**到期复核**：valid_until、review_after 到日的当前版本进入小批复核，即使 hash 不变。独立记录 temporal 覆盖，不重置普通 lint 水位、来源数或历史全量断点。无新依据不续期，也不整页隐藏历史。

生产 lint_prepare 返回页 hash/read_range；save 只认实际完整读过的范围，附 findings、evidence_paths、reviewed_pages。长页分批续查；只查几十页不能称全库已完成。旧版覆盖不能顶替新版。结构 PASS 不等于语义通过。

## 建议任务（需按自己的预算配置，不是交付保证）

| 任务 | 作用 | 控制 |
|---|---|---|
| 首次历史整理 | 按冻结队列和真实断点续跑 | 不重置、不吞掉超长源，不与每日共用游标 |
| 每日增量 | 确认答复优先，其后会议/日记/其他 | 每轮普通来源默认最多 3 份；长源仅 stage 可跨轮 |
| 每日结构巡检 | 程序扫描及少量高风险正文 | 有未处理来源而当天 0 正式入库，明确报故障 |
| 每周内容巡检 | 风险分层 + 随机抽样 + 到期复核 | 例如项目10/会议20/随机10，预算不足分批续查 |
| 可选独立验收 | 重新从原文→知识→回答抽检 | 不信任整理 Agent 自报完成 |

每约 12 次真正成功入库可触发一次关系/遗漏巡检；不是固定要建十二页。计划容量不等于实际完成。答复超过24小时无最终回执要报警；未接通 OCR/转写不能藏为“预算未审”。

## 唯一调度器

所有写任务共用单 writer，BUSY 返回本轮结束；不忙等、不抢锁、不临时加并行机器人。只暂停本次有关任务，保留用户原模型、负责人、预算和原先开关，不能恢复用户手动暂停的任务。

网络 429/503 有限指数退避；未知模型低频探测，明确请求错误暂停；连续失败、回执不一致、队列末尾需审计时停自动写并报具体原因。恢复从真实 durable journal 与来源版本开始，不用上轮口头总结推断断点。任务 completed、容器 healthy 不等于有成果。

本仓库提供 [任务提示词模板](../prompts/)，不是某平台可直接导入的任务配置；部署者需填实际工具、身份、时区、预算、模型，并真实测试一次排队运行。

## 发布同步检查

每次规则/流程/Skill/目录变化，对以下位置逐项读当前内容：

1. 库规则、根 Agent 指令、入口、路径和链接。
2. 本地 Skill、部署 Skill、Agent 平台共享 Skill（哈希仅忽略 BOM/CRLF）。
3. Bot 长期指令、关联 MCP、实际身份、当前模型。
4. 所有有关例行任务的提示词/开关/时区/模型和本地副本。
5. 看板当前卡片、负责人、状态；历史评论不重写。
6. 服务运行版本、允许目录、控制器清单及权限拒绝结果。

分别记录“已同步 / 无需修改 / 未通过”与证据。检查不强迫无关配置改版；平台未自动加载 AGENTS 就要把行为放到实际 Bot/Skill/任务入口。公开蓝图更新也不自动升级私人生产库。

## 备份与设备同步

备份原始资料、Wiki、台账、问题/答复、journal、规则、配置和加密恢复材料（秘密材料单独加密保存）。CouchDB/LiveSync 备份需数据库一致性与协议/加密元数据；简单复制可见 Markdown 不保证能恢复加密同步库。

恢复先在隔离目录/数据库演练，核文件数/哈希/附件/链接/来源回执，确认后再切换。回滚用备份和预期当前 hash，不能覆盖他人后续改动。本地参考 rollback 仅用于最近演示事务，不替代数据库恢复。

Windows、服务器、iPhone 的新增/修改/附件/冲突分别验收，检查真实字节。服务器读到不代表手机可用；手机看得到不代表已萃取。不要同时在两端编辑同一文件后无脑覆盖。
