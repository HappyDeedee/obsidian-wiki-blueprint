# 目录与数据模型

公开示例中的“工作 / 创业 / 个人”是可配置领域，不包含作者的雇主、项目或人物。

| 目录 | 职责 |
|---|---|
| `00-总入口/` | 给人的使用入口和程序生成项目导航 |
| `00-Inbox/随手放/`、`日记/` | 不要求先分类的原始记录 |
| `00-Inbox/会议/` | 录音原件、完整转写、自动纪要分开 |
| `00-Inbox/已提取正文/` | 原件的派生可读文本，带原件路径和哈希 |
| `00-Inbox/问答投稿/`、`待确认答复/` | 待核 AI 分析与真实主人答复，分别建文件 |
| `10-Sources/` | 授权历史来源、用户自述、外部资料；保留原始编号 |
| `20-Wiki/来源摘要/` | 每个来源本身的要点，不是全部知识 |
| `20-Wiki/实体/`、`人物/`、`概念/` | 按主题积累跨来源知识 |
| `20-Wiki/综合/` | 有明确问题的多来源比较与归纳 |
| `30-Projects/` | 经用户授权建立的项目当前状态、决定、候选待办和历史 |
| `40-输出/` | 生成成果；不自动当作新的独立事实来源 |
| `50-写作范本/` | 只在写作任务中参考表达，不作事实证据 |
| `90-Logs/` | 台账、问题登记、巡检、覆盖与运行历史 |
| `99-System/` | 用户维护的规则，日常 Agent 只读 |
| `00-Test/` | 临时验证，不进入事实检索 |

不要为了整齐搬动旧来源。保留旧目录和链接，通过新导航接入。需要迁移时单独制定路径映射与回滚。

## 知识页

正式类型：实体、人物、概念、来源摘要、综合、项目。示例模板在 `vault-template/99-System/模板/知识页.md`。

必需元数据：`title/domain/type/status/created/updated/sources`；可选 `aliases/source_kind/rule_version/event_date/source_date/valid_from/valid_until/review_after`。完整 YAML 列表是合法的，不依赖一行压缩文本。类型枚举不强加给来源、日志和导航。

正文先一句话说明当前结论，再写实质内容、逐项来源、待确认、历史及相关页面。重要主张按条标事实状态：

- `occurred`：原文支持已发生/已具备。
- `planned`：计划、建议、目标，不是已经实现。
- `hypothesis`：假设或推论，写清前提。
- `unverified`：原文有这项陈述，但尚未核实事实。

新页用当前公开规则版本；旧页局部改动不能冒充全页迁移完成。历史格式缺字段不等于内容错误。

## 来源身份与数量

稳定 `source_id` + 实际内容哈希才代表一个来源版本，路径只是位置；不要依赖原件 `processed:true` 跳过。会议纪要和同场完整转写是一个逻辑来源，分片及重复快照也不是独立多来源。

接收、提取、连续阅读、stage、无知识处置、首次成功、refresh、topic_repair、失败分别记录。更新同一来源不再增加“新来源成功数”；修复主题不重建来源摘要、也不推进历史队列。

原件只读；来源→知识的回链可以由 sidecar/台账/生成视图提供，不能为了回链改写原件。知识页 sources 链接到完整库内路径，并记录必要原网址/原始 ID。

## 时间不混用

`created/updated` 是文件或整理时间。`event_date` 是有证据的已发生日；`source_date` 是原始写作/发布日期；`valid_from/valid_until` 是明确适用期（截止当天仍包含）；`review_after` 是复核提醒，不等于过期。

只知道年/月就保持精度，缺年份不填当前年，不能取导入日/录音文件名补事件日期。“昨天”需要可靠原始记录日期才能换算。跨时期页面逐条写时间及依据，不用一个页面日期覆盖全部事实；通用方法不必有到期日。

## 别名、术语、人物、项目

- aliases 正本在主题页 frontmatter 的 `aliases` 列表；`20-Wiki/别名表.md` 是派生视图，由程序生成，任何人不手工维护。查询 Skill 先读别名表定位同义说法，再按分层检索。
- 别名表生成程序：`tools/maintenance.py --config PRIVATE_CONFIG aliases-full`（全量校验，带 `--publish` 才发布）、`aliases-incremental`（增量、有检查点，同样需显式发布）。生产参考 `aliases-refresh.py` 只是每批 40 项的增量包装器；`aliases-incremental.py` 是库函数，直接执行它不会刷新。两者均不能被当作现成全量安装入口。启用与调度见 [运维手册](../system/runbooks/08-operations.md) 的"程序化维护任务"节。
- 疑似同物只登记，不凭名称相近自动合并。明确错写只在派生知识中纠正并保留原话；多页同名仍核正文、范围和来源。
- 术语表由指定维护身份在核实用户原话后更新，版本递增；外部通用定义与私人用法分开。
- 概念建页须可独立定义、有独立关系、有实质内容；不是每个标题或提及都建概念。
- 实体/概念有一份充分来源即可成立；多篇提及门槛只用于巡检提醒。
- 项目由用户点名授权，或由至少两份独立来源的真实行动/交付/截止提出候选，用户确认后才建；不因无进展天数自动归档。
- 人物仅在身份有真实用户确认、领域和角色有依据时建；会议内 speaker 编号不能跨场匹配。自动声纹匹配须标自动，身份已确认不代表其业务陈述已经证实。声音向量与试听片段不进入公开 Wiki。
