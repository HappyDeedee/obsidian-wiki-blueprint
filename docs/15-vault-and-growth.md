# 知识库结构与自生长逻辑

这套方法把资料、整理后的知识、项目、生成成果和程序状态分开。目录不是装饰：不同目录决定能否改写、是否进入检索、如何回溯及是否计作新知识。

## 从空目录开始

使用 `tools/wiki.py init` 或 `tools/system.py init` 建立本地参考库，具体参数见 [本地手册](../system/runbooks/01-local.md)。不要把初始化命令指向已有私人库；迁移先保留原件并另做路径映射。

| 路径 | 内容 | 写入者与约束 |
| --- | --- | --- |
| `00-总入口/` | 使用说明、当前导航 | 导航维护程序；不是新来源 |
| `00-Inbox/随手放/`、`日记/` | 日常原始资料 | 主人/受限接收入口创建；整理 Agent 不覆盖 |
| `00-Inbox/会议/待处理/` | 等待会议链处理的录音 | 主人/同步入口；保持稳定再读取 |
| `00-Inbox/会议/日期 主题/` | 会议原录音、完整转写、派生纪要 | 会议导入器按已验证任务创建；会期未知就不补年 |
| `00-Inbox/已提取正文/` | 附件派生文字与哈希 | 附件转换服务；不代表已审阅 |
| `00-Inbox/问答投稿/` | AI 分析/候选答复 | create-only 投稿身份；尚非主人事实 |
| `00-Inbox/待确认答复/` | 主人真实答复 | 确认入口创建，保留问题 ID、版本与答复来源 |
| `10-Sources/` | 历史导入及授权来源 | 保存稳定原始 ID 和原文，不为回链改写原件 |
| `20-Wiki/来源摘要/` | 单一来源要点 | 整理提交；不能替代跨来源主题页 |
| `20-Wiki/实体/人物/概念/综合/` | 主题知识和跨来源关系 | 正式整理身份持有 writer lease 时更新 |
| `30-Projects/` | 主人授权项目、决定、动作与历史 | 候选经确认后建立；不因提及项目名直接建档 |
| `40-输出/` | 成品、报告 | 不自动反向成为新的独立事实 |
| `50-写作范本/` | 风格材料 | 只借表达，不把例子当事实 |
| `90-Logs/` | 来源台账、问题、巡检、覆盖和提交记录 | 派生运行证据，不作为原始事实循环入库 |
| `99-System/` | 规则与模板 | 主人/维护身份维护，普通查询与整理只读 |
| `00-Test/` | 虚构测试 | 排除正式事实检索和来源成功数 |

完整字段与类型约束见[数据模型](02-vault-model.md)。公开目录示例中的“工作、创业、个人”可按搭建者自己的领域调整，不能复制作者雇主、人物名单和项目。

## 第一轮整理如何开始

1. 检查目录、规则与角色权限。查询只读，投稿只创建草稿，整理身份才可提交授权知识路径。
2. 以 `source_id + 内容版本哈希` 建立来源队列；路径是当前位置，不是来源唯一身份。同一场会议的转写和纪要是同一逻辑来源。
3. 先连续读完整原文，再读相关旧页、规则和索引。长文使用分段阅读与 stage，保留真实进度；stage 本身不计整理成功。
4. 在现有知识页上提出增量：当前结论、原话/证据、时间、冲突、待确认、相关页面。只在有独立实质内容时建新主题页。
5. 不确定术语、身份或私人定义进入确认中心；缺少证据的事保留未知。来源中的历史助手文字不是当前主人授权。
6. `prepare` 固定源版本和旧页版本，正式提交前校验；提交后逐页回读，产生绑定本次来源/版本的最终回执。部分失败沿原事务恢复，不能换身份重复提交。
7. 只有终态可信回执才能推进成功数与队列。结构验证和模型语义审阅分别记录，不把其中一项代替另一项。

源码中的正式工具名和字段以 [工具合同](04-tool-contract.md)、[curation-pipeline.mjs](../system/production-reference/curation/curation-pipeline.mjs) 以及接手者自己注册并测试的 MCP schema 为准。本地参考 CLI 是教学/验证实现，不能把它的参数与生产 schema 混用。

## 怎样持续自生长

| 触发 | 读取什么 | 可以更新什么 | 成功依据 |
| --- | --- | --- | --- |
| 新资料 | 原文、相关旧页、来源台账 | 来源摘要、已有主题页、必要新页 | 首次提交的最终回执 |
| 原资料内容变化 | 新旧哈希及当前知识 | 修订事实、保留历史和修订依据 | refresh 回执，不再次计新来源 |
| 主人答复 | 问题版本、真实答复、相关原文 | 已确认词典、相关知识、问题状态 | 答复已投稿与正式已采纳分开 |
| 新会议 | 完整转写、原音频、确认身份 | 会议摘要、主题页、已授权人物证据时间线 | 导入回执 + 后续整理回执分别存在 |
| 主题修复 | 已有主题和直接来源 | 冲突、关系、重复/缺失内容 | topic_repair，不推进历史队列 |
| 结构巡检 | 路径、元数据、链接、台账 | 派生导航与明确修复候选 | 范围化报告，未知项保留 |
| 内容体检 | 原文→知识→真实问题回答 | 有证据的订正与待确认事项 | 语义比对和抽样问答结果 |

不要为每一种触发新建独立写控制器。复用单一租约/队列与现有任务，不抢占暂停任务，不覆盖主人选择的模型、负责人和开关。

## 时间、事实和人物尤其要区分

文件创建/更新时间不是事件日期；只知道年月就保留精度，未知年份不补当前年。`occurred/planned/hypothesis/unverified` 分别表示已发生、计划、推断和待核。新事实修订旧结论时保留此前适用时期，不能用新状态抹去历史。

原人物参考生成器使用的部分日期规则与通用时间规则存在差异，已列入[设备与状态手册](16-device-and-state.md)。新安装不得把文件夹日期自动宣称为经核实会期；兼容层须保留证据和不确定性。

## 新 AI 的交付清单

交付自己的私有配置位置、服务/角色清单、目录映射、任务开关、原文样例、正式提交回执、手机/电脑读回、失败恢复和备份恢复结果。必须回答：哪些只存储了、哪些已完整读过、哪些已整理、哪些经语义核验、全库还有多少未完成。

最终目标是同一套可回溯的工作方式与界面。资料不同，知识内容自然不同；只有完成实际宿主、服务和设备验收后，才能宣称自己的整套系统可运行。
