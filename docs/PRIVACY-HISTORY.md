# 历史脱敏与协作者操作

本次历史维护只清理站点专属的预置关键词和提交邮箱中的账号标识，不代表一键部署功能已验收。

## 已有克隆怎么办

1. 先把自己尚未提交的工作备份到仓库外的私有目录。
2. 重新克隆仓库。不要把旧 `.git`、旧分支或旧标签复制回来，也不要合并旧历史。
3. 如需恢复自己的改动，只迁移经过脱敏检查的文件差异，再提交到新历史。
4. 旧提交 SHA 已变化；不要再用旧 SHA 作为当前安装版本。

## 自定义问题评分

`make_question_cards.py` 保留页面类型、引用次数、问题优先级和通用噪音评分。
作者自己的业务关键词不随包提供。额外加分关键词默认关闭；如需启用，在运行环境中设置
`WIKI_CARD_PRIORITY_TERMS`，值是仅包含字符串的 JSON 数组，例如 `["示例项目"]`。
个人关键词及其运行配置不要提交到公开仓库。

## 清理范围与限制

本次检查覆盖公开分支可达的提交、文件内容、路径和归档内部条目，并检查当前文件。
历史重写不能保证收回别人已有的克隆、分叉、下载包、搜索缓存或平台保存的旧提交链接。
发现这些副本时，应按平台流程申请处理；不要声称已从互联网彻底抹除。
原始备份、敏感指纹、受影响提交清单和旧新 SHA 对照表只保存在仓库外的私有目录。
