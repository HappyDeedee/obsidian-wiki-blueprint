# 搭建整套 Wiki

保留完整仓库以解析引用。先读根 `AGENTS.md` 和 [系统入口](../../system/README.md)，再按 [检查表](../../system/INSTALL-CHECKLIST.md) 执行。公开 Skill 不能覆盖正在服务私人库的同名生产 Skill。

1. 检查实际系统、Python、Obsidian、Agent、已有服务和新库位置。缺信息仅问会改变方案的项；已有授权持续有效。凭证由使用者在私密配置中设置，不写入公开仓库或报告。
2. 按 [本地手册](../../system/runbooks/01-local.md) 在隔离目录实际运行 UI、答复与回执闭环。本地示例没有模型、声音或手机同步。
3. 按 [配置表](../../system/configuration.md) 与 02–08 手册逐步接自己的 CouchDB/LiveSync、MCP、会议、声纹、确认和唯一控制器；每一级验收后再扩大真实资料。
4. 自定义宿主和公网会话适配仍需实施，见 [源码地图](../../system/source-map.md)。读实际函数/工具 schema，注册后做权限、版本、重放和崩溃测试；不能把原版 MCP 或 Skill 当已完成权限控制。
5. 处理资料用 ingest，查询用 query，结构/语义与到期复核用 health。保留原件和时间，人工身份与自动候选分开，确认收到与已入库分开。
6. 升级前备份并核并发，保留使用者模型、开关、负责人，暂停优先于自动恢复。不创建重复 Bot/调度，不清队列重做，不复用作者 ID/连接。
7. 交付私有部署清单、能力表、同步检查、实际回执、缺项和恢复点。分别报告本地、服务器集成、真实模型语义、电脑/真手机验收；缺证据不称完成。

## 完整搭建与服务配置

接手 AI 必须阅读[服务配置与搭建总入口](../../docs/12-service-setup.md)，再按其中链接配置听悟、热词、附件转换、知识库结构及手机入口。`tools/services.py` 提供私有配置初始化和离线核验；它不会安装自定义 MCP 宿主，也不会发起云端付费任务。
